# readiness-probe

**Измеритель готовности интернет-магазина к покупкам через ИИ-агента.**

Анонимный GET, без браузерной автоматизации, без авторизации — ровно так, как работает
агент покупателя. Если товар не читается анонимным запросом, ИИ-агент его не купит.

Автор: Антон Баланов · [balanov.pro](https://balanov.pro/) · [github.com/Balanov](https://github.com/Balanov)
Лицензия: MIT. Python 3.10+, зависимостей нет.

---

## Зачем

Агент стал новым покупателем: трафик от ИИ к ритейлерам растёт на сотни процентов в год,
Shopify фиксирует ×7 трафика и ×11 заказов через ИИ, а конверсия покупателей из AI-трафика
на 42% лучше обычного поиска (Gartner, ноябрь 2026).

Одновременно Gartner отмечает, что около 40% ИИ-ассистентов пропускают товары с неполными
структурированными данными, а полная разметка `Product` есть только у 23% магазинов. То есть
проблема продавца — не цена и не логистика, а состояние данных и наличие официального пути
«агент → корзина → оплата».

Этот инструмент измеряет именно это состояние — и делает результат воспроизводимым.

## Запуск

```bash
python readiness_probe.py --targets targets.json --out out
```

Одиночная цель:

```bash
python readiness_probe.py --url "https://example.ru/catalog/" --name Example --out out
```

| Флаг | Смысл |
|---|---|
| `--deep` (по умолчанию) | Дополнительно проверяет `/robots.txt`, `/agents.txt`, `llms.txt`, `/.well-known/agent.json`, `/.well-known/ucp`, `/openapi.json` |
| `--no-deep` | Только основные замеры — примерно вдвое быстрее |
| `--discover N` | Сколько карточек товара открыть на каждой цели (по умолчанию 4) |
| `--sleep S` | Пауза между целями в секундах (по умолчанию 3) |

Выход: `out/readiness.json` (машинно) и `out/readiness.md` (человекочитаемо).

## Что измеряется

| Метрика | Как считается | Зачем |
|---|---|---|
| `status` | Код анонимного GET | 401/403/429 и нестандартные коды WAF = агент не читает витрину вообще |
| `rendered_bytes`, `text_chars` | Размер серверного HTML и объём видимого текста | Отличает настоящую витрину от SPA-оболочки |
| `jsonld_blocks`, `product_nodes` | Блоки `application/ld+json` и узлы `Product`/`Offer` | Структурированные данные — основной вход агента |
| `product_complete` | Доля `Product`-узлов со всеми обязательными полями | Агент отбрасывает позицию без них |
| `field_coverage` | Заполненность каждого поля по отдельности | Показывает, **какое именно** поле отсутствует — иначе «0 полных карточек» бесполезно |
| `microdata_products` | `itemtype="…Product"` | Запасной формат; часть читателей берёт только JSON-LD |
| `img_big` / `img_total` | Картинки с заявленным размером ≥ 600×600 | Требование каналов ИИ-агентов |
| `feeds` | Ссылки на товарные фиды (yml/xml/csv) в разметке | Открытый фид = каталог читаем без краулинга |
| `checkout.has_open_agent_checkout` | Следы `checkout_sessions`, `/.well-known/ucp`, YCP | Есть ли официальный путь «агент → корзина → оплата» |
| `surfaces` | `/robots.txt`, `/agents.txt`, `llms.txt`, `/.well-known/agent.json` | Декларирует ли сайт агентские правила |
| `agent_visible_share` | `product_complete / product_nodes` | Итоговая доля позиций, которые агент способен купить |

Обязательные поля карточки и точное правило их поиска (чтобы любую цифру можно было проверить):

| Поле | Где ищем |
|---|---|
| `name` | `name`, `title`, `headline` у сущности товара |
| `brand` | `brand`, иначе `manufacturer`, иначе `provider` (для услуг продавец и есть бренд) |
| `gtin` | **строго** `gtin`, `gtin8`, `gtin12`, `gtin13`, `gtin14` либо `identifier` с именем, содержащим gtin/ean/upc/isbn. `productID` и безымянный `identifier` GTIN не считаются |
| `sku` | `sku`, `mpn`, `productID` |
| `price` | `price`, `lowPrice`, `priceSpecification` — у сущности **или** у её `offers` |
| `priceCurrency` | `priceCurrency` — у сущности или у `offers` |
| `availability` | `availability` у сущности или у `offers` (`itemCondition` — это состояние, а не наличие, и не считается) |

Цена, валюта и наличие часто лежат в отдельном узле `Offer` без имени, поэтому
берутся из `offers` сущности, а имя — из самой сущности.

## Как принимаются карточки

Агент не останавливается на главной странице. Порядок обхода:

1. главная → 2. `sitemap.xml` / `sitemap_index.xml` → 3. карточки товара из карты →
4. если карты нет — ссылки на карточки и категории из HTML, в том числе с идентификатором
   в пути (`/smartfony-22899/`), как устроено большинство российских витрин.

Это сделано специально: иначе легко измерить не сайт, а собственную неспособность
измерителя найти товар.

## Вердикты

| Балл | Вердикт | Значение |
|---|---|---|
| ≥ 70 | READY | Агент может прочитать позицию и оформить заказ |
| 35–69 | PARTIAL | Позиции видны частично, часть выпадает из сравнения |
| < 35 | INVISIBLE | Анонимный агент каталог не читает |

## Контрольная группа

`targets_control.json` — витрины, где серверная разметка заведомо есть (Samsung RU,
IKEA RU, Leroy Merlin, OBI, BHF, Citilink, Booking.com).

Прогон по ним обязателен. Если контрольные цели тоже возвращают `INVISIBLE`, это
дефект измерителя, а не находка сайта: вывод сужается до того, что инструмент
действительно умеет, либо публикуется сам инструмент и протокол. Ложный вывод
«у всех невидимо» — самый частый и самый разрушительный дефект такого отчёта.

## Чего метод не делает

- Не оценивает качество карточек глазами человека.
- Не проверяет цены и остатки внутри личного кабинета.
- Не моделирует поведение конкретного ассистента (Алиса, ChatGPT, Perplexity).
- Не измеряет конверсию и деньги — только **структурную доступность** каталога.
- Не обходит защиту: инструмент специально не использует браузерную автоматизацию,
  чтобы показать реальную картину, а не картину «для роботов, которым разрешено всё».

Если витрина отдаёт SPA-оболочку или стоит за WAF — это и есть результат измерения,
а не сбой инструмента. В JSON это видно по полям `pages_probed`, `sitemap_product_urls`
и списку `notes`.

## Воспроизводимость

Каждая цифра отчёта получена прогоном этого скрипта. Результаты лежат в `results/` и
коммитятся в репозиторий. Повторный запуск на тех же целях воспроизводит те же значения
в пределах изменений на стороне сайта.

## Структура

```
readiness_probe.py      измеритель
targets.json            21 витрина: основной набор
targets_control.json    7 витрин: контрольная группа
results/                машинные и человекочитаемые результаты прогона
results_control/        результаты контрольной группы
```
